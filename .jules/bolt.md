## 2024-05-19 - Prevent Layout Thrashing in Interactive Hover Effects
**Learning:** The codebase implements cursor-following visual effects (`initOrangeHover` and `initMagnetic` in `js/main.js`) using continuous pointer event listeners (`mousemove`/`pointermove`). Previously, these listeners synchronously called `getBoundingClientRect()` followed by setting inline style properties (`setProperty`, `transform`) on the DOM node. This caused forced synchronous layout (layout thrashing) because the browser had to repeatedly calculate geometry on every pixel of pointer movement to resolve the read-write-read cycle.
**Action:** Always cache bounding box measurements (`getBoundingClientRect()`) for high-frequency interactive UI effects using `mouseenter` or explicit target tracking, and reset/invalidate the cache on `mouseleave` and `scroll` events to keep layout calculations out of the hot path.
