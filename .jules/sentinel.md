## 2024-05-18 - XSS in HTML Attributes from Inadequate DOM-based escapeHtml
**Vulnerability:** The `escapeHtml` function in `js/main.js` used a DOM-based approach (`div.textContent = str; return div.innerHTML;`). While this correctly escaped `<` and `>`, it **failed to escape double (`"`) and single (`'`) quotes**. Because the return value of `escapeHtml` was heavily used inside HTML template literals within attributes (e.g., `alt="${escapeHtml(project.title)}"`), an attacker could supply input with quotes like `project.title = 'Hello" onload="alert(1)"'` to break out of the attribute and inject an event handler or script.
**Learning:** DOM-based HTML escaping via `textContent` to `innerHTML` only escapes tags and ampersands by default. It is not sufficient when the escaped string will be inserted into an HTML attribute.
**Prevention:** Always use regex-based replacements (or a dedicated library like `he` or DOMPurify) to escape `&`, `<`, `>`, `"`, and `'` completely when building HTML strings, especially when inserting user data into attributes.
