## 2024-05-24 - [CRITICAL] Fix attribute injection XSS in escapeHtml
**Vulnerability:** The `escapeHtml` function used DOM text node assignment (`div.textContent = str; return div.innerHTML;`) to escape HTML. This method correctly escapes `<`, `>`, and `&`, but fails to encode single and double quotes (`'` and `"`). When the resulting output is interpolated into HTML attributes (e.g., `alt="${escapeHtml(project.title)}"`), an attacker can inject quotes to break out of the attribute context and inject arbitrary HTML or script tags, leading to a Cross-Site Scripting (XSS) vulnerability. Additionally, passing a non-string value could lead to type confusion since `textContent` might not cast correctly in all edge cases depending on usage, although mainly a quote escaping vulnerability here.
**Learning:** Never rely on DOM `textContent` assignment to encode values that will be used inside HTML attributes. Attribute values must have quotes escaped to prevent attribute injection. Also, custom escaping functions must robustly handle non-string inputs (like `null` or `undefined`) to avoid type confusion errors when manipulating string prototypes or calling `.replace()`.
**Prevention:** Use a comprehensive regex-based escaping function that replaces all sensitive characters (`&`, `<`, `>`, `"`, `'`) and ensures safe type casting before manipulation.
