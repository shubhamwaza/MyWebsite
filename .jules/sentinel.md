## 2024-05-24 - [DOM-based escapeHtml XSS Pattern]
**Vulnerability:** The existing `escapeHtml` function used DOM injection (`div.textContent = str; return div.innerHTML;`) to escape text. This method fails to escape quotation marks (`"` and `'`), making it vulnerable to Cross-Site Scripting (XSS) when the escaped string is injected into HTML attributes (e.g., `<img alt="${escapeHtml(value)}">`). Additionally, without type checking, a non-string input (like null or an object) would be stringified (e.g., `"null"` or `"[object Object]"`) rather than safely ignored, which could cause type-confusion XSS vulnerabilities depending on context.
**Learning:** In vanilla JS setups lacking a framework's built-in robust escaping, native DOM escaping is insufficient for attributes. It's an easy anti-pattern to fall into because it effectively escapes `<`, `>`, and `&` for standard text nodes, giving a false sense of security while leaving attributes completely exposed to breakout.
**Prevention:** Always use regex-based character replacement for `&`, `<`, `>`, `"`, and `'` to comprehensively escape untrusted data for all HTML contexts. Additionally, ensure the function casts inputs to strings or returns empty strings for nullish values to prevent type-confusion issues.
